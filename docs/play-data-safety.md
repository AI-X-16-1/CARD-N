# Google Play — Data safety 양식 답변 (초안)

> **초안입니다.** 코드를 읽고 작성했습니다. 제출 전에 §6의 판단이 필요한 항목 3개를
> 확인하시고, §7의 선행 조건이 충족됐는지 보세요.
>
> 이 답변은 `docs/privacy-policy.md`와 **반드시 일치해야 합니다.** 구글은 둘이 어긋나면
> 등록을 거부하고, 나중에 발견되면 앱을 내립니다.

---

## 1. 먼저 — 구글의 정의

양식을 잘못 채우는 대부분의 원인이 용어를 상식대로 읽기 때문입니다.

- **수집(Collected)** = 데이터가 **기기를 떠나는 것**. 앱이 권한을 요구했는지, 화면에
  보여줬는지와 무관합니다. 단말 안에서만 쓰고 전송하지 않으면 **수집이 아닙니다.**
- **공유(Shared)** = 데이터를 **제3자에게 전달**하는 것. 다만 "우리를 대신해 처리하는
  서비스 제공자(processor)"에게 넘기는 것은 예외로 볼 여지가 있습니다 — §6 참조.
- **일시적 처리(Ephemeral)** = 메모리에서 요청 처리에 필요한 시간만큼만 쓰고 저장하지
  않는 것. 임시 파일로라도 디스크에 쓰면 해당하지 않는다고 보는 편이 안전합니다.

## 2. 수집하는 데이터 (기기를 떠남)

전부 **필수(Required)**, 목적은 전부 **앱 기능(App functionality)**입니다. 분석·광고·
개인화 목적 없음.

| Play 분류 | 데이터 유형 | 실제 내용 | 공유 |
|---|---|---|---|
| Personal info | Name | 연락처(명함 주인) 이름, 내 명함 이름 | **예** |
| Personal info | Email address | 명함의 이메일, 내 명함 이메일 | 아니요 |
| Personal info | Phone number | 명함의 전화번호, 내 명함 전화번호 | 아니요 |
| Personal info | Address | 명함의 주소, 우편번호 | 아니요 |
| Personal info | Other info | 회사, 부서, 직함, 메모 | **예** (회사·직함) |
| Photos and videos | Photos | 촬영·선택한 명함 이미지 | 아니요 |
| Audio | Voice or sound recordings | 요약을 위해 업로드한 녹음 파일 | 아니요 (음성 자체는 미전송) |
| App activity | Other user-generated content | 대화 요약, 관계도, 게임 카드 | **예** (전사·요약) |
| Device or other IDs | Device or other IDs | 앱이 생성한 설치 식별자 | 아니요 |

**"Device or other IDs"에 체크하는 이유**: 광고 식별자나 하드웨어 고유번호가 아니라 앱이
첫 실행 때 만든 난수입니다. 그래도 구글의 정의("특정 기기·브라우저·앱에 결부된 식별자")에
들어가고, **이 앱에는 계정이 없어 이 값이 이용자를 구분하는 유일한 수단**이므로 신고하는
것이 맞습니다.

## 3. 수집하지 않는 데이터

| Play 분류 | 왜 아닌가 |
|---|---|
| Contacts → Contacts | `READ_CONTACTS` 권한을 쓰지만 **기기를 떠나지 않습니다.** 통화 녹음을 찾을 때 전화번호에 맞는 이름을 단말에서 조회하는 용도뿐입니다. |
| Location | 수집·요청 자체가 없습니다. |
| Financial info / Health / Messages | 해당 없음. |
| App activity → App interactions, Crash logs, Diagnostics | **분석·크래시 리포팅 SDK를 넣지 않았습니다.** Sentry·Firebase·Amplitude 전무. |

권한을 요구한다고 수집이 되는 것이 아니라는 점이 여기서 갈립니다. 주소록 권한은 요구하지만
주소록은 수집하지 않습니다.

## 4. 제3자 공유 — Google (Gemini API)

개인정보가 외부로 나가는 **유일한 경로**입니다. 두 기능이 호출합니다.

| 기능 | 전송 내용 |
|---|---|
| 대화 요약 | **대화 전문(전사 텍스트)**, 상대 이름·회사·직함, 만난 횟수, 이전 요약들 |
| 게임 카드 문구 | 상대 **이름**, **회사**, 직군, 등급 |

게임 카드 쪽도 이름과 회사를 보냅니다 — 능력치만 보내는 것이 아닙니다.

명함 인식(OCR)과 음성 인식(STT)은 **자체 서버에서 처리**하므로 이미지와 음성 파일은
외부로 나가지 않습니다.

## 5. 보안 및 삭제 관련 답변

| 질문 | 답 | 근거 |
|---|---|---|
| 전송 중 데이터가 암호화되나요? | **예** | HTTPS. **§7 선행 조건 참조** |
| 이용자가 데이터 삭제를 요청할 수 있나요? | **예** | 앱에서 연락처·대화를 직접 삭제. 추가로 방침 §10의 문의처 |
| 아동 대상 앱인가요? | 아니요 | |
| 독립 보안 검토를 받았나요? | 아니요 | 받지 않았으면 "예"로 답하면 안 됩니다 |
| 계정 삭제 경로가 있나요? | 해당 없음 | 계정 자체가 없습니다 |

**삭제 관련 보충** — 구글은 "계정 삭제" 요구사항을 계정이 있는 앱에 적용합니다. 이 앱은
계정이 없어 해당하지 않지만, **앱을 삭제해도 서버 데이터는 남습니다**(기기 식별자가 사라져
본인도 접근 못 할 뿐). 방침에 명시했고, 문의처를 통한 삭제 요청 경로를 열어둬야 합니다.

## 6. ⚠️ 제출 전에 판단이 필요한 항목 3개

제가 임의로 정하지 않고 남겨둡니다. 셋 다 "더 많이 신고하는 쪽"이 안전합니다.

### 6-1. Gemini 전송을 "공유(Shared)"로 신고할 것인가

구글은 **"우리를 대신해 처리하는 서비스 제공자"** 에게 넘기는 것을 공유에서 제외할 여지를
둡니다. Gemini API는 그 성격에 가깝지만, 판단은 계약 조건과 데이터 사용 방식에 달려
있습니다.

- **"공유 아님"으로 신고** → Gemini를 처리위탁으로 보는 해석. 더 가볍지만 틀리면 위반.
- **"공유함"으로 신고** ← **권장.** 대화 전문이 외부 회사 서버로 나가는 건 사실이고,
  과다 신고로 문제되는 경우는 없습니다.

위 §2 표는 **공유함으로 신고하는 안**으로 작성했습니다.

### 6-2. 음성 파일을 "일시적 처리"로 체크할 것인가

음성은 STT 직후 삭제되지만, **처리 중에는 임시 파일로 디스크에 씁니다**
(`stt.py`가 `finally`에서 unlink). 엄밀히는 "메모리에서만" 이 아닙니다.

→ **체크하지 않기를 권장합니다.** 일시적 처리로 신고하면 의무가 줄어드는 대신, 잘못
신고했을 때 문제가 됩니다.

### 6-3. 전사 텍스트를 별도 항목으로 볼 것인가

전사는 **저장하지 않지만 Gemini로 전송됩니다.** 위 표에서는 "App activity → Other
user-generated content"에 묶었습니다. 심사자가 음성의 파생물로 볼 수도 있어 해석 여지가
있습니다 — 묶어두되, 방침에 전송 사실을 명시해 뒀으니 불일치는 아닙니다.

## 7. ⚠️ 선행 조건 — 지금은 "예"로 답하면 안 되는 항목

**"전송 중 암호화"에 예로 답하려면 실제로 HTTPS여야 합니다.**

현재 개발 환경은 평문 HTTP입니다(`http://10.0.2.2:8000`). 배포 시 Cloudflare Tunnel로
HTTPS를 붙이기로 했고, **그 전에는 이 항목에 "예"로 답할 수 없습니다.**

확인 방법: 앱이 실제로 쓰는 `EXPO_PUBLIC_API_URL`이 `https://`로 시작하는지, 그리고
`android:usesCleartextTraffic`이 켜져 있지 않은지.

## 8. 제출 시 유의

- 이 답변과 `docs/privacy-policy.md`의 내용이 **한 항목이라도 어긋나면 안 됩니다.**
  특히 §4의 Gemini 전송 내용과 방침 §6이 같은 내용을 말하는지 확인하세요.
- 양식은 언제든 수정 가능하지만, 수집 항목이 늘어나면 **먼저 양식을 고치고 배포**해야
  합니다.
- 기능을 추가할 때 이 문서를 같이 갱신하지 않으면 금방 어긋납니다. 특히 분석 SDK를
  넣는 순간 "Analytics" 목적과 "Crash logs" 항목이 새로 생깁니다.
